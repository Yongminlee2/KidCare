# 우리아이 지킴이 (KidCare)

부모 폰과 아이 폰에 같은 앱을 하나씩 깔고, 첫 실행 때 역할을 고르면 연결되는 자녀 관리 안드로이드 앱입니다.

아이가 하루를 어디서 어떻게 보냈는지를 **지도 위의 선과 사람이 읽는 글**로 보여주고, 부모가 아이 폰의 소리·진동을 원격으로 바꾸거나 잃어버린 폰을 울려 찾을 수 있게 합니다.

## 무엇을 만들고 무엇을 안 만들었나

**만든 것**

- 6자리 코드로 부모 폰과 아이 폰을 연결
- 아이 폰의 위치를 움직임에 맞춰(멈춰 있으면 5분, 움직이면 30초) 수집하고, 하루를 **머무름/이동 구간**으로 묶어 요약
- 부모 폰에서 지도(경로선 + 마지막으로 확인한 위치)와 타임라인, 날짜별 조회
- 아이 폰의 소리·진동 원격 변경, 핸드폰 찾기, 시간대별 자동 전환
- 지도에서 찍은 장소에 아이가 도착하거나 나서면 부모 폰에 알림
- 부모가 아이 폰에 한마디 보내기, 부모가 맞추는 알람시계
- 배터리가 낮거나 권한이 꺼지면 부모 폰에 알림

**의도적으로 안 만든 것**

- **몰래 감시(아이콘 숨김).** 아이 폰에 앱 아이콘이 보이고, 알림줄에 "위치 공유 중"이 항상 떠 있습니다. 아이도 자기 상태를 볼 수 있습니다. 접근성 서비스로 다른 앱을 훔쳐보는 방식은 쓰지 않았습니다.
- **기기관리자 권한으로 앱 삭제 막기.** 오작동하면 폰 초기화까지 얽히는데, 아이 폰에 걸어두기엔 위험이 이득보다 큽니다. 그 위 단계인 기기 소유자 등록은 **아이 폰 공장 초기화**가 전제라 아예 하지 않기로 했습니다. 대신 부모가 물어봤는데 대답이 없으면 부모에게 알립니다.
- **WiFi 원격 제어.** 안드로이드 10부터 서드파티 앱은 WiFi를 켤 수 없습니다. 유일한 길인 기기 소유자 등록은 위와 같은 이유로 막혔고, 옛 API를 되살리려고 `targetSdk`를 내리면 위치 수집이 망가집니다.
- **통화·문자·앱 사용시간 감시.** 이 앱의 범위가 아닙니다.

**배포 방식**: 가족끼리 APK 직접 설치. 플레이스토어에 올리지 않습니다.

## 구조

```
com.kidcare.family
├─ logic/       순수 코틀린. 안드로이드 API 미사용 → JVM 단위 테스트 대상
│  ├─ InviteCode         6자리 초대 코드 생성·정규화·검증
│  ├─ LocationFilter     올릴 위치인지 판정 (정확도·이동거리·속도)
│  ├─ SegmentBuilder     위치 점 → 머무름/이동 구간
│  ├─ SegmentSummarizer  구간 → 시각·기간·거리 표기
│  ├─ ScheduleResolver   시간대 규칙 겹침·자정 넘김 해석
│  ├─ GeofenceEvaluator  장소 진입/이탈 판정 (히스테리시스·중복 억제)
│  ├─ TrailCodec         하루 문서 인코딩과 점 개수 상한(경로 축약)
│  ├─ MovementTrailFilter 이동 중 GPS 후보에서 흔들림·순간이동 걸러내기
│  ├─ DisconnectRule     "물어봤는데 대답이 없다" 판정
│  └─ DayPicker          날짜 이동과 헤더 문구
├─ core/        Firestore 접근만
│  ├─ AuthGateway        익명 로그인 (동시 호출 가드)
│  ├─ FamilyRepository   가족 생성·페어링·서버 시각 보정
│  ├─ TrailRepository    하루 문서(trails/{dayKey}) 읽기/쓰기
│  ├─ CommandRepository  원격 명령 (전달 수단은 인터페이스 뒤에 숨김)
│  ├─ PlaceRepository    장소 (+ 저장하면 아이 폰에 다시 읽으라고 알림)
│  ├─ EventRepository    사건 쓰기·구독·읽음 표시
│  ├─ ScheduleRepository 시간대 규칙
│  └─ ErrorText          예외 → 사람이 읽는 한국어 안내
├─ onboarding/  역할 선택, 양쪽 페어링, 자녀 권한 안내
├─ child/       아이 폰 전용 — 상시 포그라운드 서비스와 그 부속
└─ guardian/    부모 폰 전용 — 탭 다섯(지도·알림·관리·예약·장소)과 알림 수신 서비스
```

**설계 원칙 하나**: 계산은 `logic/`에, Firestore는 `core/`에, 화면·서비스는 `child/`·`guardian/`에 둡니다. `logic/`이 안드로이드 API를 쓰지 않기 때문에 까다로운 로직(자정을 넘는 시간대 규칙, GPS 흔들림 속에서 "머물렀다"를 판정하는 것)을 전부 JVM 테스트로 고정할 수 있습니다.

### 데이터 흐름

```
[아이 폰]                       [Firestore]                [부모 폰]
위치 수집 (30초/5분)
  → 필터 통과분을 폰 안에만 쌓음 (메모리 + 파일, 통신 0)

포그라운드 서비스의 리스너 ◄─────  commands/  ◄──────────  '지금 위치 확인'
  → 하루치를 다시 묶어
  → trails/{dayKey}       ──►  trails/{dayKey} ────────►  타임라인 + 경로선
  → 현재 상태 덮어쓰기      ──►  children/{uid}  ────────►  마커 + 배터리
  → state 갱신            ──►                  ────────►  "전달 중… → 완료"

장소 도착·이탈, 배터리, 권한
  → 사건 하나씩            ──►  events/  ──────────────►  알림 탭 + 시스템 알림
```

원격 명령을 FCM 푸시가 아니라 **Firestore 실시간 리스너**로 전달합니다. 아이 폰은 위치 수집 때문에 어차피 포그라운드 서비스가 상시 돌고 있어서, FCM이 사주는 "잠든 앱 깨우기"가 여기서는 필요 없기 때문입니다. 덕분에 Cloud Functions(유료 요금제)를 쓰지 않습니다. 전달 수단은 인터페이스 하나 뒤에 감춰서, 나중에 FCM으로 갈아끼워도 부르는 쪽 코드는 그대로입니다.

**아이 폰은 주기적으로 아무것도 올리지 않습니다.** 부모가 물어봤을 때와 하루 한 번 안전 업로드, 그 두 순간에만 서버를 건드립니다. 그래서 부모 화면은 "지금 위치"라고 말하지 않고 "12분 전 확인한 위치예요"처럼 언제인지를 같이 적습니다. 왜 이렇게 바꿨는지는 아래 개발일지의 "무료 한도" 절에 있습니다.

## 개발일지

### 1~2단계 — 뼈대와 페어링, 위치 수집

앱 하나에 두 역할을 넣고, 부모가 만든 6자리 코드를 아이가 입력하면 연결되는 구조를 만들었습니다. 코드 알파벳에서 `0/1/O/I/L`을 뺐습니다 — 아이가 화면을 눈으로 읽고 손으로 옮겨 적는 코드라, 잘못 읽히면 연결이 실패하고 원인도 안 보입니다.

아이 폰은 상시 포그라운드 서비스가 위치를 받아 필터를 거칩니다. 이때는 50m 이상 움직였을 때만 통과시키고, 정확도가 100m를 넘거나 시속 200km를 넘는 이동은 GPS 오류로 보고 버렸습니다. (**두 숫자는 그 뒤 바뀌었습니다** — 지금은 25m, 그리고 정확도 문턱이 평소 50m·15분 굶으면 100m로 두 단계입니다. 통과한 점을 곧바로 서버에 올리는 것도 이제 안 합니다 — 아래 "무료 한도" 절.)

**이 단계에서 잡은 것들**

- **익명 로그인 동시 호출 버그.** 화면 두 개가 동시에 로그인하면 익명 계정이 두 개 생기고, 화면이 든 ID와 실제 로그인된 ID가 어긋납니다. 당장은 화면이 하나뿐이라 안 터지지만, 백그라운드 서비스가 도는 순간 **"위치가 그냥 안 올라가는데 이유를 모르겠는"** 형태로 나타났을 겁니다. 보안 규칙이 ID가 안 맞는 쓰기를 조용히 거부하기 때문입니다.
- **약속과 동작의 불일치.** 화면에 "연결이 끝난 뒤에는 바꿀 수 없습니다"라고 써놓고, 실제로는 버튼을 누르는 순간 역할이 잠겼습니다. 엄마가 자기 폰에서 실수로 `아이`를 누르면 앱 데이터를 통째로 지우는 것 말고는 되돌릴 방법이 없었습니다.

### 보안 규칙 — 가장 오래 걸린 부분

Firestore 보안 규칙만 **리뷰 3회, 재작성 2회**를 거쳤습니다. 자녀 관리 앱에서는 **아이가 곧 공격자**입니다. 아이는 폰을 손에 쥐고 있고 앱의 접속 키도 갖고 있어서, 앱을 거치지 않고 데이터베이스를 직접 두드릴 수 있습니다. 앱 코드에서 아무리 검사해도 규칙이 뚫려 있으면 소용이 없습니다.

실제로 잡힌 구멍들:

1. **모든 가족의 초대 코드가 새어나갔다.** Firestore에서 `read` 권한은 "문서 하나 읽기"와 "컬렉션 전체 목록 긁기"를 둘 다 엽니다. 이걸 착각해서 목록만 열린다고 주석까지 달아놨었습니다. 로그인만 하면 **전 가족의 초대 코드를 통째로** 받아갈 수 있었습니다.
   → 코드를 **문서 이름으로** 쓰는 별도 컬렉션(`inviteCodes/A2C4K9`)으로 분리했습니다. 코드를 정확히 아는 사람만 꺼내갈 수 있고 목록 조회는 완전히 막힙니다.

2. **아무나 남의 가족에 보호자로 등록할 수 있었다.** 멤버 생성 규칙이 "본인 ID로 쓰는가"만 검사했습니다.
   → 가족을 만든 사람만 보호자가 되고(`ownerUid` 대조), 자녀는 **자기가 입력한 코드를 증거로 제출**해 서버가 대조하도록 바꿨습니다.

3. **막았더니 옆문이 열려 있었다.** 위 둘을 고친 뒤에도, 가입한 아이가 **자기 문서의 역할을 `보호자`로 바꿔** 부모를 가족에서 삭제할 수 있었습니다. 만드는 문(create)은 잠갔는데 고치는 문(update)이 열려 있던 겁니다.
   → 역할과 가입 코드를 생성 후 불변으로 만들었습니다.

4. **명령 기능을 열면서 또 한 번.** 4단계에서 부모가 명령을 쓸 수 있게 규칙을 추가할 때, 기존 재귀 와일드카드를 남겨두면 **아이도 계속 명령을 쓸 수 있습니다**(규칙은 OR로 평가). 아이가 자기 폰에 `소리 켜기` 명령을 스스로 넣어 무음 예약을 무력화할 수 있었습니다.
   → 와일드카드를 없애고 하위 컬렉션을 하나씩 명시했습니다.

### 3단계 — 하루를 글로 바꾸기

위치 점 수백 개를 "몇 시부터 몇 시까지 어디에 있었고 언제 어디로 이동했는지"로 바꾸는 단계입니다.

**머무름 판정의 핵심은 "연속 2개" 규칙**입니다. 실내에서는 GPS 좌표가 수십 미터씩 흔들리고 가끔 수백 미터를 튑니다. 반경을 벗어난 점 **하나**로 머무름을 끊으면 학교에 있는 6시간이 수십 개 구간으로 쪼개져 타임라인을 읽을 수 없게 됩니다. 그래서 벗어난 점이 연속 2개 나와야 머무름이 끝납니다. 5분을 못 채운 정지(신호 대기 같은 것)는 이동에 흡수합니다.

**이 단계에서 잡은 것들**

- **무료 한도를 태울 뻔했다.** 구간을 다시 계산할 때마다 하루치 위치를 처음부터 다시 읽게 돼 있었습니다. 점이 쌓일수록 읽는 양이 늘어서 하루 최대 **3만 6천 건** — 무료 한도가 5만이고 그건 부모 폰 몫까지 합친 총량입니다. 넘으면 경고가 뜨는 게 아니라 **그날 나머지 시간 동안 앱이 그냥 멈춥니다.**
  → 아이 폰이 자기가 방금 올린 점을 메모리에 들고 있게 바꿔 **하루 2건**으로 줄였습니다.
- **하루가 항상 24시간은 아니다.** 하루의 끝을 "시작 + 24시간"으로 계산하고 있었습니다. 한국은 서머타임이 없어 지금은 안 터지지만, 가족이 해외에 나가면 **한 시간치 위치가 어느 계산에도 안 잡혀 영영 사라집니다.** 달력 기준으로 바꿨습니다.
- **아이가 권한 하나로 추적을 반쯤 무력화할 수 있었다.** 배터리를 아끼려고 "가만히 있을 땐 5분, 움직이면 1분"(지금은 5초)으로 전환하는데, 아이가 멈춰 있는 동안 활동 감지 권한을 끄면 "움직이기 시작했다"는 신호가 올 길이 없어 **밖에 나가 돌아다녀도 계속 5분마다만** 확인하게 됩니다. 부모 화면에는 5분 전 위치가 떠 있고 이유는 안 보입니다.
  → 권한이 사라진 것을 감지하면 곧바로 이동 주기로 되돌립니다. 배터리보다 위치 신뢰성이 먼저입니다.

### 무료 한도 — 가족 하나가 하루 1,100번을 썼습니다

무료(Spark) 요금제의 쓰기 한도는 **프로젝트 전체에서 하루 2만 번**입니다. 1,000가족을 담으려면 가족당 하루 20번이어야 합니다. 실제로 세어 보니 **1,100번**이었습니다 — 55배.

세어 보기 전까지는 아무도 몰랐습니다. 3단계에서 걱정한 것은 읽기였는데(위 "무료 한도를 태울 뻔했다"), 정작 벽에 먼저 부딪히는 쪽은 쓰기였습니다. 위치 한 점마다 문서를 하나 만들고 상태 문서를 한 번 덮어쓰니 하루 1,040번, 거기에 15분마다 도는 구간 재계산이 하루치 구간 문서를 통째로 갈아끼워 50번이 더 붙었습니다.

고친 방향은 **"주기적으로 올리는 것을 전부 없애고, 부모가 물어볼 때만 올린다"**입니다. 하루치를 문서 하나(`trails/{dayKey}`)로 합치고, 아이 폰은 위치를 폰 안에만 쌓다가 부모가 '지금 위치 확인'을 누를 때와 하루 한 번 안전 업로드에만 올립니다. 1,100번이 28~32번이 됐습니다.

**이 개편에서 잡은 것**

- **연결 끊김 배너가 정확히 반대로 동작할 뻔했습니다.** 그 배너의 판정은 "아이 폰이 30분 넘게 상태 문서를 안 고쳤으면 끊긴 것"이었는데, 그 상태 문서를 주기적으로 고치던 코드가 바로 이 개편에서 사라졌습니다. 그대로 뒀다면 **완전히 정상인 폰이 30분마다 무조건 끊긴 것으로** 보였을 겁니다. 기능이 없어지는 것보다 나쁩니다 — 부모가 몇 번 헛경보를 겪고 나면 진짜로 끊긴 날에도 그 문구를 안 읽습니다. 판정 재료를 "물어봤는데 대답이 없는가"로 바꿨습니다(`logic/DisconnectRule`).
- **35배 줄였지만 들어가지는 않았습니다.** 1,000가족 기준으로 여전히 1.4~1.6배 초과였고, 5단계가 이벤트를 더하면서 1.8~2.1배가 됐습니다. 반올림해서 "됐다"고 적지 않으려고 숫자와 계산 과정을 [`docs/known-issues.md`](docs/known-issues.md) 12·14번에 그대로 남겼습니다. 가족 하나가 혼자 쓰는 동안에는 한참 아래라, 지금은 막는 조건이 아니라 기록입니다.

### 5단계 — 장소 알림, 메시지, 부모가 맞추는 알람

부모가 지도에서 찍은 장소에 아이가 도착하거나 나서면 부모 폰에 알림이 오고, 한마디를 보내거나 알람을 맞출 수 있는 단계입니다.

**이 단계에서 잡은 것들**

- **새 보안 규칙이 옛 규칙 뒤에 숨을 뻔했다.** `events`에 "아이만, 자기 이름으로, 읽지 않은 상태로 만들 수 있다"는 규칙을 새로 넣었는데, 같은 컬렉션에 1단계 때 넣어둔 `allow create: if memberOf(familyId)` — 즉 가족이면 아무나 무엇이든 — 이 그대로 남아 있었습니다. **Firestore 규칙은 OR로 평가**되므로 새 규칙을 아무리 조여도 옛 블록 하나가 통과시켜 버립니다. 아이가 남의 이름으로 사건을 지어내거나, 미리 '읽음'으로 만들어 부모의 안 읽음 목록에서 지운 채로 넣을 수 있었습니다. 4단계에서 재귀 와일드카드로 똑같이 당한 자리라, 이번에는 옛 블록을 지우지 않고 **그 자리에서 고쳐 쓰고** 옆에 "블록을 하나 더 만들지 말 것"을 적어뒀습니다.
- **부모 폰 알림이 하루 18시간 조용히 죽을 뻔했다.** 아이 폰이 부모 폰을 깨울 수단(FCM)이 없어서, 부모 폰에도 `events`를 상시 구독하는 서비스를 하나 둡니다. 그 서비스의 종류를 `dataSync`로 적었는데 **안드로이드 15부터 `dataSync`는 24시간 중 6시간만 돌 수 있습니다.** 나머지 18시간은 서비스가 시스템에 끊기고, 화면에는 아무 표시도 없이 알림만 안 옵니다. 이 앱은 플레이스토어에 올리지 않는 사이드로드 전용이라 `specialUse`가 정당하게 쓸 수 있는 종류였고, 그쪽으로 바꿨습니다.
- **장소를 만들자마자 "도착했어요"가 떴다.** 처음에는 "그 장소에 대한 기록이 없는데 지금 안에 있으면 도착"으로 판정했습니다. 그런데 이 앱에서 그 상황은 새로 깐 폰이 아니라 **부모가 아이가 이미 있는 곳에 장소를 만드는 순간**이 압도적으로 흔합니다. 저장을 누르는 그 자리에서 "집에 도착했어요"가 뜨는데, 시각까지 '방금'으로 찍혀 세 시간 전에 있었던 도착을 지어내는 셈이었습니다. 지금은 처음 보는 장소는 **알리지 않고 상태만 조용히 심습니다.**
- **아무도 못 본 알림이 다음 진짜 알림을 잡아먹었다.** 같은 장소에서 5분 안에 두 번 알리지 않는 중복 억제가 있는데, 이 5분 시계를 "전환이 일어난 시각"으로 밀고 있었습니다. 그래서 부모가 도착 알림을 꺼둔 장소에서 아이가 들어갔다 나오면, **아무에게도 안 보인 도착이 시계를 되감아** 그 뒤의 진짜 이탈 알림이 사라졌습니다. 시계를 미는 기준을 "실제로 부모에게 알린 순간"으로 바꿨습니다.

**전수 리뷰에서 하나 더**

- **부모가 맞춘 알람이 회수될 수 있는 프로세스에서 울고 있었다.** 알람은 매니페스트 리시버 하나에서 시작하는데, 그 5분 동안 앱에 포그라운드 서비스가 하나도 없을 수 있습니다 — 아이가 위치 권한을 껐으면 위치 서비스는 스스로 멈추지만 걸어둔 알람 예약은 그대로 남기 때문입니다. 시스템이 그 프로세스를 회수하면 **소리가 조용히 끊깁니다** — 소리도 진동도 없이 그냥 멎습니다. 부모는 알람을 걸었고, 아이는 안 깼고, 어느 화면에도 아무 말이 없는 실패입니다. 우는 동안만 사는 작은 포그라운드 서비스를 두어 막았습니다.
- **"알림이 없어요"와 "못 불러왔어요"가 같은 화면이었다.** 목록 화면 셋이 전부 `목록이 비었는가` 하나로 빈 목록 문구를 띄우고 있어서, 보안 규칙을 아직 게시하지 않은 상태에서는 오류 한 줄과 "아직 온 알림이 없어요"가 **같은 크기로 동시에** 떴습니다. 부모는 가운데 큰 글씨를 읽고 조용한 하루로 이해하는데 실제로는 아무것도 못 읽은 상태입니다. 세 화면이 이제 못 불러옴 / 불러오는 중 / 정말 비었음을 구분합니다.

### 6단계 — 통신이 끊겼을 때, 막다른 골목, 그리고 배포용 빌드

오프라인 처리는 **새로 만들 것이 거의 없었습니다.** Firestore 안드로이드 SDK는 로컬 캐시와 쓰기 큐를 기본으로 켜 두기 때문입니다(SDK를 직접 열어 확인했습니다 — `persistenceEnabled = true`, 캐시 100MB). 이 단계가 실제로 한 일은 **그 사실을 코드에 적고, 화면이 거짓말하지 않게 만든 것**입니다.

핵심은 읽기와 쓰기가 정반대로 움직인다는 것이었습니다. 읽기는 캐시로 즉시 답하고, **캐시에 없으면 "없는 문서"로 답합니다.** 쓰기는 반대로 큐에는 즉시 들어가지만 **서버가 확인해 줄 때까지 완료되지 않고, 제한시간이 없습니다.** 이 비대칭 하나가 화면 여러 곳을 거짓말하게 만들고 있었습니다.

**이 단계에서 잡은 것들**

- **서버 시각을 재는 함수가 화면 두 개를 얼려 버렸습니다.** 부모 폰 시계와 서버 시계의 차이를 재는 코드가 있는데, 재는 방법이 **쓰기**였습니다(자기 멤버 문서에 서버 시각을 적고 즉시 다시 읽는 방식). 오프라인에서는 그 쓰기가 영영 안 끝나므로 이 함수도 안 끝납니다. 지도 상단 카드가 이 값을 기다리고 있어서 **그 뒤에 그려야 할 타임라인까지 통째로 안 그려졌습니다.** 오류도 스피너도 없이 빈 화면입니다. 제한시간을 두되 **시간 초과로 물러난 값은 캐시하지 않습니다** — 여기서 "차이 0"을 굳혀 버리면 초대 코드 만료가 다시 부모 폰 시계로 계산돼, 예전에 고쳤던 "만들자마자 죽은 코드" 버그가 되살아납니다.
- **"보냈어요"가 거짓말이었습니다.** 오프라인에서 명령을 보내면 쓰기가 큐에 들어간 것이지 아이 폰에 간 것이 아닙니다. 그런데 화면은 "전달 중…"에서 영영 안 벗어났습니다 — 60초 무응답 타이머가 **쓰기가 끝난 뒤에** 시작하도록 돼 있어서 그 타이머조차 시작하지 못했기 때문입니다. 지금은 15초가 지나면 "아직 안 갔어요 … 그 사이 상황이 달라졌을 수 있어요"라고 적습니다. 이때 "명령이 나갔다"는 전제로 화면을 고치는 콜백은 **일부러 부르지 않습니다** — 부르면 울리지도 않는 폰에 '소리 끄기' 버튼을 띄우고, 걸리지도 않은 알람을 "맞춰져 있어요"로 적습니다.
- **읽으면서 찾은 데이터 유실.** 보안 규칙이 사건의 발생 시각을 "서버 시각 기준 과거 24시간 안"으로 묶어 두는데, 큐에 밀려 있던 사건은 **일어난 시각**을 들고 있다가 연결이 돌아온 **지금** 도착합니다. 즉 **24시간을 넘겨 끊겨 있으면 그 초과분의 사건이 통째로 거부됩니다.** 30시간이면 처음 6시간 것이 사라집니다. 앱은 알아챌 수도 없습니다 — 거부는 쓰기를 기다리던 코루틴에만 전달되는데, 하루가 넘는 단절 동안 아이 폰 프로세스는 여러 번 죽었다 살아나고 큐를 다시 보내는 새 프로세스에는 기다리는 사람이 없습니다. 지도에는 그날 경로가 멀쩡히 그려지는데 "학교에 도착했어요"만 없는 모양이 됩니다. 이번 단계에서 고치지 않고(규칙 변경은 범위 밖) 조건과 숫자를 적어 뒀습니다.
- **"오류가 발생했습니다"만 있고 누를 것이 없는 화면들.** 여섯 가지 막다른 골목을 코드로 확인했는데 **셋은 이미 멀쩡했고 그대로 뒀습니다.** 진짜 막다른 골목은 셋이었습니다 — 첫 실행이 비행기 모드일 때(실패 문구만 있고 버튼이 없었습니다), 부모가 가족을 지웠을 때(아이 폰이 계속 "엄마 아빠랑 이어져 있어요"라고 말하고 있었습니다), 그리고 **구글 플레이 서비스가 없거나 옛 버전일 때**. 마지막 것은 저장소 어디에서도 확인한 적이 없었습니다 — 없으면 위치와 지오펜스가 **콜백도 예외도 없이** 죽는데, 서비스는 떠 있고 알림줄도 그대로여서 부모 화면의 마커만 멈춥니다.
- **아이콘의 새싹이 사라졌습니다.** 앱에 아이콘 선언 자체가 없어 기본 로봇이 떠 있었습니다. 새싹이를 적응형 아이콘 규격에 맞춰 앉히고 배경을 지도 핀과 같은 하늘색으로 골랐는데, **실제 크기(48dp)로 그려 보니 잎이 보이지 않았습니다.** 잎 색과 배경색이 색상만 다르고 밝기가 거의 같아서, 작아지면 두 색이 하나로 뭉쳐 새싹이가 그냥 웃는 얼굴이 됩니다 — 아이콘을 만든 이유가 정확히 사라지는 실패입니다. 더 밝은 배경으로 바꿔 잡았습니다. **"되겠지"로 넘기지 않고 실제 크기로 그려 봤기 때문에** 보인 것입니다.
- **R8이 모델의 게터 스무 개를 지웠습니다.** 배포용 빌드에서 코드 축소를 켰는데, Firestore가 문서를 데이터 클래스로 바꿀 때 쓰는 게터들이 **난독화된 게 아니라 통째로 사라졌습니다**(쓰는 데가 없으니 지운 겁니다). 인자 없는 생성자도 함께 사라져서, 객체를 만들 수조차 없는 상태였습니다. 이 고장은 크래시가 아니라 **빈 화면**입니다 — 앱은 멀쩡히 돌고 모든 화면이 비어 보입니다. 보호 규칙을 하나씩 지워 보며 각 규칙이 정말 필요한지 확인했고, **아무것도 안 하는 규칙 하나는 도로 지웠습니다**(하는 일 없는 보호 규칙을 남기면 결국 전부 다 지키게 됩니다). 리소스도 7,000개에서 4,775개로 줄었는데, 앱이 직접 선언한 343개 중 사라진 것은 참조가 하나도 없는 4개뿐임을 이름으로 확인했습니다.

### 후속 개선 — 화면 재설계와 5초 이동 경로 (2026-08-08)

기능 구조는 유지하면서 런처 아이콘, 역할 선택, 아이 홈, 보호자 탭 다섯 개의 색상·아이콘·간격을 한 체계로 다시 맞췄습니다. 지도는 아이 위치를 더 가까이 보는 줌 18을 기본으로 하고, 날짜 한 줄만 남긴 채 이동 기록을 접고 펼칠 수 있게 바꿨습니다. 기존 지도는 하루 원시 위치점이 문서에 있는데도 구간 끝점만 연결해 골목과 회전이 잘렸습니다. 이제 저장된 원시점을 시간순으로 이어 실제 경로를 그립니다.

이동 중 위치 후보는 30초가 아니라 **5초마다** 받습니다. 하지만 GPS 후보를 전부 기록하지는 않습니다. 활동 인식이 정지라고 판단한 동안에는 경로 파일에 쓰지 않고, 이동 상태에서도 50m보다 부정확한 점·5초 미만 간격·두 점의 오차반경 안에서 생긴 흔들림·시속 200km를 넘는 순간이동은 제외합니다. 실내 실기기에서 정지한 폰이 2~5m/s라는 잘못된 속도를 보고하는 것을 확인해, 정확도가 10m 이내인 야외 GNSS 속도만 보조 근거로 쓰도록 고쳤습니다.

아이 폰의 로컬 원본에는 2,000점 제한을 걸지 않습니다. Firestore의 하루 문서만 1MB 상한을 피하려고 최대 2,000점을 유지합니다. 초과한 날은 예전처럼 오래된 점을 버리지 않고, 출발·도착과 큰 회전을 우선 보존하는 경로 축약으로 하루 전체를 담습니다. 머무름·이동 요약은 축약하기 전 로컬 원본 전체로 계산합니다. 따라서 서버 쓰기 횟수는 부모가 확인할 때 하루 문서 한 건이라는 기존 구조를 그대로 유지합니다.

검증은 보호자·아이 역할의 갤럭시 두 대에서 진행했습니다. 아이 폰 서비스 로그에서 `이동 5초` 요청과 재시작 복구를 확인했고, 실내 정지 상태에서 15초 동안 경로 파일이 114줄에서 늘지 않았습니다. 디버그 APK 빌드와 단위 테스트 121개가 통과했습니다. 남은 실사용 확인은 실제 보행·차량 경로의 모퉁이 품질과 하루 배터리 소모입니다.

### 3D 아이콘과 화면 마스코트 통일 (2026-08-08)

선택한 3D 캐릭터를 런처 아이콘으로 적용하고, 같은 얼굴·민트색 지도 핀·새싹·하트 형태를 유지한 투명 배경 마스코트를 별도로 제작했습니다. 역할 선택, 아이 홈, 연결, 권한 안내, 메시지, 휴대폰 찾기, 초기 로딩 화면까지 일곱 화면의 기존 평면 마스코트를 이 이미지로 교체했습니다.

작은 버튼 아이콘과 지도 마커는 3D로 바꾸면 실제 표시 크기에서 형태가 뭉개지므로 기존 벡터를 유지했습니다. 기능 코드와 화면 구조는 건드리지 않았으며, 단위 테스트와 축소된 릴리스 빌드를 통과한 뒤 갤럭시 실기기에 `versionName 0.6`을 덮어 설치해 투명 배경·잘림·표시 크기를 확인했습니다.

## 아이가 앱을 강제 종료하면 — 막을 수 없고, 대신 부모에게 알립니다

아이 폰에서 **설정 → 애플리케이션 → 우리아이 지킴이 → 강제 중지**를 누르면 이 앱은 멈춥니다. 권한도 비밀번호도 필요 없습니다.

그러면 안드로이드가 앱을 "stopped" 상태로 두는데, 그 상태에서는 **부팅 신호(`BOOT_COMPLETED`)가 배달되지 않고 걸어둔 알람이 전부 취소됩니다.** 원격 명령 수신, 되돌리기, 시간대 예약, 그리고 **위치 추적까지** 한꺼번에 멎습니다. 폰을 껐다 켜도 살아나지 않습니다.

**되살리는 방법은 하나입니다 — 아이 폰에서 앱을 한 번 열면 됩니다.** 열기만 하면 서비스가 다시 뜨고 알람도 다시 걸립니다.

**막지 않기로 했습니다.** 이걸 막으려면 기기관리자(Device Admin) 권한이 필요한데, 그건 오작동하면 폰 초기화까지 얽히는 권한이라 아이 폰에 걸어두기엔 위험이 이득보다 큽니다(위 "의도적으로 안 만든 것" 참고). 사이드로드로 깔린 일반 앱이 자기 강제 종료를 막는 방법은 안드로이드에 없습니다.

**대신 부모에게 말합니다.** 예전에는 부모가 명령을 하나 보내고 60초를 기다려 "애기폰이 응답하지 않아요"를 볼 때까지, 그것도 관리 탭에서만 알 수 있었습니다. 지금은 보호자 화면 맨 위에 배너가 뜹니다 — 지도 탭이든 관리 탭이든 같은 자리입니다.

```
⚠️ 오후 2:31에 보낸 요청에 애기폰이 아직 대답하지 않았어요
아이 폰에서 '우리아이 지킴이' 앱을 한 번 열어주세요. 그러면 다시 이어져요.
```

판정은 **"물어봤는데 대답이 없는가"**입니다(`logic/DisconnectRule`). 세 조건을 전부 만족해야 뜹니다 — ① 한 번이라도 물어본 적이 있고, ② 그 마지막 물음 뒤로 대답이 없고, ③ 그 물음이 **30분** 넘게 묵었을 때.

"아이 폰에서 30분 넘게 아무 신호가 없으면"이 **아닙니다.** 아이 폰은 이제 주기적으로 아무것도 올리지 않으므로(위 "무료 한도" 절), 침묵 자체는 정상 상태입니다. 물어본 적 없는 폰은 대답하지 않은 것이 아닙니다 — 페어링만 끝내고 '지금 위치 확인'을 한 번도 안 눌러 본 부모에게 "연결이 끊겼어요"라고 말하는 것은 거짓말입니다.

30분인 이유는 한 번의 무응답(터널, 절전 낮잠)으로 헛경보를 내지 않기 위해서입니다. 5분이나 10분으로 잡으면 멀쩡한 폰에 헛경보가 나고, 헛경보가 몇 번 나면 부모는 진짜로 끊긴 날에도 이 문구를 안 읽습니다. 아이 폰이 대답하면 배너는 저절로 사라집니다 — **실패(`failed`)도 대답으로 칩니다.** 실패 이유를 적어 보낼 수 있었다는 것 자체가 살아 있다는 뜻이니까요.

판정 재료는 **부모 폰 안에만** 있습니다(언제 물었고 언제 대답이 왔는가, 두 값). 서버에 두면 그것을 읽고 쓰는 것 자체가 무료 한도를 먹고, 두 값을 적는 것도 빼는 것도 같은 폰이라 폰 시계가 어긋나 있어도 차이는 정확합니다.

### 실기기 검증 (갤럭시 A16 · 안드로이드 16)

1~3단계 전체를 실제 폰에서 확인했습니다.

- 설치·역할 선택·익명 로그인
- 보호자 가족 생성과 초대 코드 발급 (3회, 매번 정상)
- **자녀 페어링** — 배포된 보안 규칙을 실제로 통과
- 권한 안내 → 자녀 홈 → 포그라운드 서비스 기동, 상시 알림 유지
- 위치 수집·필터 동작, 구간 재계산
- **지도(타일·마커·경로선)와 타임라인**
- 날짜 이동, 오늘 기준 다음 날 버튼 비활성
- "역할 다시 고르기"로 저장값이 완전히 초기화되는지

폰이 한 대뿐이라 **아이 폰 역할은 PC 스크립트로 대신했습니다** — 실제 두 번째 폰과 같은 방식으로 익명 로그인하고 같은 보안 규칙을 통과해 데이터를 넣습니다.

**실기기가 아니면 못 잡았을 문제 3개**

1. 오류가 **영어 원문**(`PERMISSION_DENIED: Missing or insufficient permissions.`)으로 떴습니다. 부모가 이걸 보고 할 수 있는 게 없습니다 → 한국어 안내로 교체.
2. **실패했다면서 로딩 표시가 계속 돌았습니다.** 이건 전수 리뷰가 *"오류 문구가 바로 위에 있으니 괜찮다"* 며 넘겼던 항목인데, 실제 화면에서는 스피너가 글자보다 눈에 잘 띄어 "아직 하는 중"으로 읽혔습니다. **코드만 읽고 UI를 판정하면 안 된다**는 걸 확인한 사례라 판단을 뒤집고 고쳤습니다.
3. **Firestore 복합 색인이 없으면 타임라인이 영원히 빕니다.** 지도는 멀쩡하고 목록만 비어서 "데이터가 없나 보다"로 보입니다. 예외 객체를 통째로 로그에 남기도록 해둔 덕에 생성 링크를 로그에서 건질 수 있었습니다. (이 색인은 지금 필요 없습니다 — 타임라인이 쿼리 대신 하루 문서 한 건을 ID로 곧장 읽게 바뀌었습니다.)

### 배포용 빌드 확인 (6단계)

코드 축소를 켠 APK를 아이 폰에 실제로 깔아 확인했습니다. 14.2MB → **3.7MB**.

- 자녀 홈 화면이 정상적으로 그려지고, `versionCode = 6`, 디버그 플래그 없음
- 릴리스 서명이 다르면 기존 설치에 덮이지 않으므로(`INSTALL_FAILED_UPDATE_INCOMPATIBLE`), 같은 APK를 디버그 키로 다시 서명해 깔았습니다 — 서명 외 811개 항목이 바이트까지 동일함을 확인했습니다

**아직 못 본 것**: 그때 부모 폰이 연결돼 있지 않아서, **문서를 객체로 바꾸는 일이 가장 많은 화면들**(지도의 '지금 위치 확인', 소리 변경, 보호자 탭 다섯)은 릴리스 빌드에서 아직 눌러 보지 못했습니다. 가장 빠른 확인법은 장소를 하나 등록하고 아이 폰 로그에서 `지오펜스 N개 등록`을 보는 것입니다 — `N`이 0이면 반경 값이 객체로 안 옮겨졌다는 뜻입니다.

## 설정하고 빌드하기

자세한 절차는 [`docs/setup.md`](docs/setup.md)에 있습니다. 요약하면:

1. **Firebase 프로젝트 생성** → 안드로이드 앱 추가(패키지 `com.kidcare.family`) → `google-services.json`을 `app/`에 저장
2. **익명 인증** 켜기, **Firestore** 생성(`asia-northeast3`, 프로덕션 모드)
3. **보안 규칙 게시** — `firestore.rules` 내용을 콘솔 `규칙` 탭에 붙여넣고 게시
4. **복합 색인 생성** — 필요한 것은 `commands`(`state` + `createdAt`) **하나뿐**입니다. 앱을 한 번 실행하면 아이 폰 로그에 생성 링크가 나옵니다
5. 빌드

```bash
./gradlew.bat :app:assembleDebug
```

무료 Spark 요금제로 충분합니다. 카드 등록이 필요 없습니다. **가족 하나가 쓰는 동안에는** 한도의 한참 아래입니다 — 여러 가족으로 늘리려 할 때의 계산은 [`docs/known-issues.md`](docs/known-issues.md) 12·14번에 있습니다.

배포용(서명 + 코드 축소) 빌드는 키스토어가 필요합니다. 절차는 [`docs/setup.md`](docs/setup.md)의 "릴리스 서명" 절에 있습니다.

- **빌드가 통과하는 것은 아무 증거도 아닙니다.** 이 저장소에서 폰으로만 잡힌 결함이 다섯입니다 — `VIBRATE` 권한 누락으로 폰찾기가 통째로 죽어 있던 것, 상태바 겹침, 밤 모드에서 마스코트가 배경에 묻힌 것, 장소 지도가 대서양 한가운데로 열린 것, 아이콘의 새싹이 48dp에서 사라진 것. 전부 빌드도 테스트도 통과했습니다.

### 코드 작성 규칙

- **`CancellationException`은 어떤 일반 `catch`·`runCatching`보다 먼저 다시 던집니다.** 이 저장소에서 같은 사고를 아홉 번 고쳤습니다.
- 프래그먼트는 `onDestroyView`에서 리스너를 전부 해제하고 바인딩을 `null`로 둡니다. 늦게 오는 콜백은 바인딩 `null` 검사로 막습니다.
- **osmdroid 지도를 코드로 옮길 때는 되돌아오는 이벤트를 막으세요.** `setZoom`/`setCenter`가 그 자리에서 `Scroll`/`ZoomEvent`를 되쏩니다. 그 리스너가 "지도 중심 = 사용자가 고른 좌표"로 상태를 되받아쓰면 아직 안 옮겨진 지도의 중심(0,0)이 좌표로 저장됩니다. `PlaceFragment.suppressMapCallbacks`가 그 방어입니다.
- 사용자에게 보이는 문구는 전부 `strings.xml`, 한국어. 실패 문구는 `core/ErrorText.errorMessage(...)`를 거칩니다 — SDK 원문이 부모에게 보이면 안 됩니다.
- 주석은 한국어로 **왜** 를 적습니다. 집필 기준은 `core/AuthGateway.kt`.
- 커밋 메시지는 한국어. **도구·AI 흔적을 남기지 마세요.**

### 함께 고쳐야 하는 짝

한쪽만 바꾸면 컴파일은 되는데 조용히 안 도는 자리들입니다.

- **새 명령 타입** → `core/model/Documents.kt`의 `CommandType` + `child/CommandHandler.kt`의 `when` + 보내는 화면. 셋 다.
- **새 이벤트 타입** → `EventType` + `guardian/AlertAdapter.kt`의 `when`. 상수를 참조하면 컴파일러가 잡아줍니다(리터럴 쓰지 마세요).
- **장소를 바꾸는 경로** → 반드시 `guardian/PlaceFragment.kt`의 `writeThenNotify`를 지나야 합니다. 그 함수가 쓰기 뒤에 `SYNC_RULES`를 보냅니다. 안 지나면 아이 폰이 지오펜스를 다시 걸지 않아, **지운 장소의 알림이 계속 울립니다.**
- **`firestore.rules`를 고쳤으면** → 사람이 콘솔에서 **다시 게시**해야 합니다. 로컬 파일만 바꾸면 아무 효과가 없습니다. 순서는 **APK 먼저 설치, 규칙 나중 게시**입니다.

### 사람이 직접 해야 하는 것 (코드로 대신 못 함)

1. **보안 규칙 게시** — Firebase 콘솔 → Firestore Database → 규칙 → `firestore.rules` **전체** 붙여넣기 → 게시. 콘솔은 통째로 갈아끼우는 방식이라 바뀐 부분만 넣으면 페어링·명령 규칙이 날아갑니다.
2. **복합 색인 생성** — `commands`(`state` + `createdAt`) 하나. 없으면 명령이 하나도 안 갑니다.
3. **릴리스 키스토어** — 지금 저장소의 것은 **개발용**입니다. 남에게 배포하기 전에 반드시 교체하고, 한 번 배포한 뒤에는 절대 바꾸지 마세요(업데이트가 막힙니다).

## 알려진 제약

- **재설치하면 가족이 깨집니다.** 익명 로그인이라 앱을 지우면 ID가 바뀌는데 양쪽 다 되돌릴 길이 없습니다. 아이 폰에 "다시 연결" 버튼을 다는 것은 **아이가 스스로 감시를 풀 수 있게 된다**는 뜻이라 설계 판단이 필요해 보류 중입니다.
- **하루 구분을 아이 폰 날짜로 찍습니다.** 아이가 폰 날짜를 하루 앞으로 돌리면 그 뒤 기록이 부모가 못 가는 날짜에 저장됩니다. 보안 규칙으로는 막을 수 없습니다(서버가 대조할 기준이 없는 클라이언트 값이라).
- **아이가 앱을 강제 종료하면 전부 멎습니다.** 막을 방법이 없어서 막지 않고, 대신 부모 화면에 배너로 알립니다 — 위 ["아이가 앱을 강제 종료하면"](#아이가-앱을-강제-종료하면--막을-수-없고-대신-부모에게-알립니다) 참고.
- **7일 넘게 통신이 끊기면 그 초과분의 알림이 사라집니다.** 위치 기록은 멀쩡히 올라가는데 "학교에 도착했어요" 같은 사건만 서버가 거부합니다(보안 규칙이 사건 시각을 과거 7일로 묶고 있어서). 앱도 부모도 알아챌 수 없습니다. 원래 24시간이었는데 폰을 하루만 꺼놔도 그 사이 알림이 통째로 사라져서 7일로 넓혔습니다 — 넓힌 근거와 하한을 아예 없애지 않은 이유는 [`docs/known-issues.md`](docs/known-issues.md) 20번에 있습니다.
- **아이가 그럴듯한 거짓 알림을 만들 수 있습니다.** 아이 폰은 이 앱의 접속 키를 갖고 있어서 앱을 거치지 않고 사건을 직접 쓸 수 있습니다. 막으려면 사건을 폰이 아닌 곳(유료 요금제)에서 만들어야 합니다 — 받아들이기로 한 것이지 놓친 것이 아닙니다(known-issues 15번).
- **아이 폰의 하루 종일 실사용은 아직 미검증입니다.** 보호자·아이 역할의 실기기 두 대에서 설치와 정지 필터까지 확인했지만, 삼성 절전 정책이 하루 동안 서비스를 유지하는지와 5초 고정밀 위치가 실제 배터리를 얼마나 쓰는지는 장시간 들고 다녀야 확인할 수 있습니다.
